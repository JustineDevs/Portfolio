# Release v0.1.1

Release notes for `v0.1.1` (since `v0.1.0` / `67f41c1`).

## Highlights

- **Release lane**: GitHub Release workflow supports manual backfill for already-existing tags, and `v0.1.0` was backfilled successfully from Actions.
- **Auth hardening**: Admin Google OAuth now warns about invalid `AUTH_URL` / `NEXTAUTH_URL` usage, and the env/docs now match Auth.js host expectations to avoid `redirect_uri_mismatch`.
- **Asset reliability**: Image URLs are normalized across CMS/public content for local paths, GitHub blob/raw links, protocol-relative URLs, Google Drive, and Dropbox. Broken remote assets fall back instead of taking down the Three.js image pipeline.
- **Markdown content**: `bodyMd` now renders as real GitHub-flavored markdown with images, tables, code blocks, line breaks, and GitHub-style alert boxes such as `> [!NOTE]` and `> [!WARNING]`.
- **About CMS**: The About editor is positioned as a personal editorial surface for story, learning, methodology, philosophy, and under-the-hood thinking. Editorial section keys replaced the old resume-like naming with backward-compatible migration logic.
- **Build unblock**: Follow-up fix for Vercel production builds corrects the `rehype-github-alerts` import shape and supplies local markdown-plugin declarations so the shared markdown renderer passes typecheck in CI.

## Changed

- Social nav links now point explicitly to GitHub `releases`, `tags`, and `stargazers`.
- Vercel Analytics and Speed Insights mount only when explicitly enabled via env flags.
- Project/About/blog content rendering now shares a common markdown renderer and personal-content framing.
- Project tags and technologies now render as badges in the showcase details section.
- `types/markdown-plugins.d.ts` now pins the markdown plugin module declarations used by the renderer instead of relying on transitive type availability.

## Upgrade / ops

- If you want Vercel telemetry, enable the project features first and then set:
  - `NEXT_PUBLIC_ENABLE_VERCEL_ANALYTICS=true`
  - `NEXT_PUBLIC_ENABLE_VERCEL_SPEED_INSIGHTS=true`
- For Auth.js, keep `AUTH_URL` / `NEXTAUTH_URL` as a single origin only, such as `https://jstn.site`, not callback paths.
- Existing About rows with old keys are read through a compatibility layer; saving them from the CMS rewrites them to the new editorial key names.
- Release backfill for an already-existing tag can be run from GitHub Actions `Release` with a `tag` input.
